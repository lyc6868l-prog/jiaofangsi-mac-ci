## 二、v1.4 修订目标

v1.4 在 v1.3 基础上修复以下 6 个问题：

1. 修复 `LaunchGatePage` 早于应用级认证对象创建的顺序冲突
2. 冻结应用级认证对象的唯一注入机制
3. 修复通过受限路由直达模块的绕过风险
4. 明确首版设备绑定策略不是“严格机器级绑定”，而是“安装实例级绑定”
5. 明确 `LoginPage` 持有页面级瞬时 UI 状态，不再写成纯 `StatelessWidget`
6. 补齐 `LoginCard` 本地状态与安全存储状态的迁移边界

## 五、只读核查结论

### 5.1 正式应用入口现状

当前正式链路：
- `apps/dj_flutter/lib/main.dart`
- `apps/dj_flutter/lib/app/app.dart`
- `apps/dj_flutter/lib/app/router/app_router.dart`

当前事实：
- `main.dart` 直接运行 `DjFlutterApp`
- `DjFlutterApp` 使用 `MaterialApp(onGenerateRoute: AppRouter.onGenerateRoute)`
- `homePath` 当前直接进入 `AppShellPage`

结论：
- 会话恢复不能直接塞进同步路由函数
- 必须先建立应用级认证对象，再进入专门承载异步恢复的 `LaunchGatePage`

### 5.2 登录模块现状

当前文件：
- `apps/dj_flutter/lib/features/auth/presentation/pages/login_page.dart`
- `apps/dj_flutter/lib/features/auth/presentation/widgets/login_card.dart`
- `apps/dj_flutter/lib/preview_login.dart`

当前事实：
- `LoginPage` 自己有一套完整登录 UI 和假逻辑
- `LoginCard` 也有一套完整登录 UI 和假逻辑
- `preview_login.dart` 直接使用 `LoginCard`
- `LoginCard` 当前带有硬编码历史账号和明文示例密码
- `LoginCard` 仍通过 `SharedPreferences` 存免责声明隐藏状态

结论：
- 必须收口成唯一正式实现
- 必须明确哪些状态继续留在 Flutter 本地，哪些迁出
- 明文演示数据必须删除

### 5.3 主壳现状

当前文件：
- `apps/dj_flutter/lib/app/shell/app_shell_page.dart`
- `apps/dj_flutter/lib/app/shell/feature_card/glass_card.dart`
- `apps/dj_flutter/lib/app/shell/user_center_panel.dart`
- `apps/dj_flutter/lib/app/shell/workspace_module.dart`

当前事实：
- 功能卡片当前全部可点击
- `GlassCardGrid` 仍在 `glass_card.dart` 内部
- `UserCenterPanel` 是静态假数据
- `WorkspaceModule` 会根据 `section` 直接加载模块页
- `AppShellPage` 当前不做 section 权限归一化

结论：
- 权限控制不能只落在卡片点击层
- 必须在主壳层阻止通过受限路由或初始 section 直达模块

### 5.4 状态注入现状

当前事实：
- 仓库内未发现现成 Provider / InheritedWidget / GetIt / AuthSessionStore 接入设施
- `DjFlutterApp` 当前只是直接返回 `MaterialApp`

结论：
- 必须在文档中冻结一套唯一注入机制
- 否则应用级单实例仍会在实现时变成现场决策

## 六、v1.4 冻结后的唯一架构

### 6.1 总链路

```text
main.dart
  -> 创建应用级认证对象
      -> AuthSessionStore
      -> AuthController
      -> PythonAuthTaskBridge
      -> PythonGuestTaskBridge
  -> DjAppScope
      -> DjFlutterApp
          -> AppRouter.homePath
              -> LaunchGatePage
                  -> AuthSessionStore.bootstrap()
                      -> AuthController.restoreSession()
                  -> 会话有效 -> AppShellPage
                  -> 会话无效 -> LoginPage
                      -> LoginCard
                          -> AuthController.login() / registerGuest()
                              -> 成功后返回 homePath
```

### 6.2 应用级对象创建顺序

冻结结论：

1. 先创建应用级认证对象
2. 再把这些对象挂到统一应用作用域
3. 再运行 `DjFlutterApp`
4. 再由 `LaunchGatePage` 使用已存在的 store/controller 完成 bootstrap

这意味着：
- `LaunchGatePage` 不负责创建认证对象
- `LaunchGatePage` 只负责读取与触发启动恢复

### 6.3 唯一注入机制

冻结结论：

- 新增 `DjAppScope`
- `DjAppScope` 负责向子树暴露：
  - `AuthSessionStore`
  - `AuthController`
  - `PythonAuthTaskBridge`
  - `PythonGuestTaskBridge`
- 页面统一从 `DjAppScope.of(context)` 读取依赖
- 不采用全局裸静态变量
- 不采用页面级手工层层透传
- 不引入新三方状态管理依赖

建议形式：
- `InheritedWidget` 或 `InheritedNotifier` 封装应用级对象

### 6.4 主壳取态的唯一方式

冻结结论：
- 主壳统一从 `DjAppScope` 取得 `AuthSessionStore`
- 再读取 `store.snapshot`
- 不再让 `AppShellPage` 强制新增 `authState` 构造参数
- 不保留“构造参数传值”和“全局读取”双方案并存

### 6.5 正式登录承载结论

冻结结论：
- `LoginPage` 是正式页面容器
- `LoginPage` 必须改为 `StatefulWidget`
- `LoginCard` 是唯一正式登录 UI 组件
- `LoginPage` 原有自绘输入区、按钮区、演示逻辑不再保留为正式实现
- `preview_login.dart` 仅用于 UI 预览，不接正式业务

### 6.6 权限控制冻结结论

冻结结论：
- 卡片置灰只是 UI 层表现
- 真正的访问控制必须下沉到 `AppShellPage`
- `AppShellPage` 在 `initState` 和 section 切换时都必须对 section 做权限归一化
- 非 VIP / 游客若命中受限模块，必须回退到 `overview` 或 `unlockTool`

### 6.7 设备绑定冻结结论

冻结结论：
- 首版不是“严格机器级绑定”
- 首版冻结为“安装实例级绑定”
- 具体方式为：应用首次生成并持久化设备标识
- 该策略可满足首版落地稳定性，但不能写成严格不可重置的机器绑定

### 9.1 `LaunchGatePage` 状态机

```text
idle
  -> bootstrapping
    -> userSessionValid -> gotoShell
    -> guestSessionValid -> gotoShell
    -> noSession -> gotoLogin
    -> restoreError -> gotoLoginWithMessage
```

### 9.2 `LoginPage` 状态机

```text
idle
  -> loadingPrefill
  -> submittingLogin
    -> loginSuccess -> gotoHome
    -> loginFailed -> showError
  -> submittingGuest
    -> guestSuccess -> gotoHome
    -> guestFailed -> showError
```

### 9.3 对象关系图

```text
main.dart
  -> 创建 AuthSessionStore / AuthController / bridges
  -> DjAppScope
      -> DjFlutterApp

LaunchGatePage
  -> 从 DjAppScope 读取 AuthSessionStore / AuthController
  -> 调用 store.bootstrap() 或 controller.restoreSession()

LoginPage
  -> 从 DjAppScope 读取 AuthSessionStore / AuthController
  -> 维护 submitting / errorMessage / prefillLoaded
  -> 调用 controller.login() / controller.registerGuest()

AppShellPage
  -> 从 DjAppScope 读取 AuthSessionStore.snapshot
  -> 做 section 权限归一化
  -> 向 GlassCardGrid / UserCenterPanel 提供同一份快照
```

## 十、状态模型冻结

### 10.1 `AuthSessionSnapshot`

```dart
enum AuthSessionKind {
  anonymous,
  user,
  guest,
}

class AuthSessionSnapshot {
  final AuthSessionKind kind;
  final String? token;
  final String? guestToken;
  final String? userId;
  final String? email;
  final String? nickname;
  final bool isVip;
  final DateTime? tokenExpiresAt;
  final DateTime? vipExpiresAt;
  final String? remainingTime;
  final String? errorMessage;
  final bool needNetworkValidation;

  bool get canEnterShell => kind == AuthSessionKind.user || kind == AuthSessionKind.guest;
  bool get isGuest => kind == AuthSessionKind.guest;
}
```

### 10.2 `AuthSessionStore`

```dart
class AuthSessionStore extends ChangeNotifier {
  AuthSessionSnapshot _snapshot = ...;
  bool _bootstrapped = false;

  AuthSessionSnapshot get snapshot => _snapshot;
  bool get bootstrapped => _bootstrapped;

  Future<void> bootstrap(AuthController controller) async;
  void update(AuthSessionSnapshot snapshot);
  void clear();
}
```

冻结职责：
- `bootstrap()` 只负责首次恢复
- 登录、游客进入、登出、刷新权益后都更新同一个 `snapshot`
- 主壳、登录页、启动页读取的是同一个状态源

### 10.3 `AuthController`

```dart
class AuthController {
  Future<AuthSessionSnapshot> restoreSession();
  Future<AuthSessionSnapshot> login({required String email, required String password, required bool remember, required bool autoLogin});
  Future<AuthSessionSnapshot> registerGuest();
  Future<AuthSessionSnapshot> refreshEntitlement();
  Future<AuthSessionSnapshot> refreshProfile();
  Future<void> logout();
}
```

冻结职责：
- 不直接持有 UI 状态
- 不负责页面跳转
- 负责把 bridge 结果组装为统一快照

### 10.4 `LoginPage` 页面级瞬时状态

`LoginPage` 必须持有：
- `bool _submitting`
- `String? _errorMessage`
- `LoginPrefill? _prefill`
- `bool _prefillLoaded`

这些状态属于页面瞬时 UI 状态，不进入 `AuthSessionStore`。

## 十四、Python 文件实施细则

### 14.1 `secure_storage.py`

冻结职责：
- 保存有效会话 token
- 保存游客会话 token
- 保存登录预填邮箱
- 保存 remember / autoLogin 偏好
- 首版不默认保存可还原密码

最小接口：

```python
class SecureStorage:
    def save_user_session(self, session: dict) -> None: ...
    def load_user_session(self) -> dict | None: ...
    def clear_user_session(self) -> None: ...

    def save_guest_session(self, session: dict) -> None: ...

    def clear_guest_session(self) -> None: ...

    def save_login_prefill(self, payload: dict) -> None: ...
    def load_login_prefill(self) -> dict | None: ...
```

加密要求：
- 使用 PBKDF2 + Fernet
- 固定业务盐值与 100000 次迭代
- 存储目录使用平台标准目录

## 二十、验收标准汇总

### 20.1 功能验收

| 功能点 | 验收标准 |
|---|---|
| 首页启动 | `homePath` 进入 `LaunchGatePage` |
| 启动恢复 | `LaunchGatePage` 可异步恢复用户或游客会话 |
| 正式登录实现 | 正式业务只有一套登录 UI 与登录逻辑 |
| 明文演示数据 | 登录页不再保留硬编码账号和示例密码 |
| 登录功能 | 点击登录可真实调用 API 并进入主壳 |
| 游客注册 | 点击游客可真实调用 API 并进入主壳 |
| 受限路由拦截 | 非 VIP / 游客无法通过受限 section 直达模块 |
| 权益控制 | VIP 全功能可用，非 VIP / 游客仅解锁工具可用 |
| 用户中心 | 展示真实资料与权益状态 |
| 登出功能 | 清理会话后返回登录页 |
| 游客宽限期 | 断网 6 小时内可继续使用游客模式 |

### 20.2 技术验收

| 技术点 | 验收标准 |
|---|---|
| Python RPC | `auth` / `guest` 模块可正确处理请求 |
| Flutter bridge | 可正确调用 Python runtime |
| 应用级认证对象 | controller / bridge / store 不在页面中重复创建 |
| 唯一注入机制 | 全部页面统一从 `DjAppScope` 取依赖 |
| 主壳取态 | 主壳统一读取 `AuthSessionStore` |
| 协议规范 | schema 与 runtime 动作一致 |

### 20.3 安全验收

| 安全点 | 验收标准 |
|---|---|
| 本地存储 | 使用 PBKDF2 + Fernet |
| 本地密码 | 不默认保存可还原密码 |
| 客户端密钥 | 不内置共享 HMAC 密钥 |
| 锁定策略 | 以服务端为准 |
| 设备绑定 | 首版明确为安装实例级绑定 |
| 演示数据 | 不保留明文示例账号与密码 |

## 二十二、风险与应对

### 22.1 技术风险

| 风险点 | 影响 | 应对措施 |
|---|---|---|
| 认证服务器不可达 | 登录失败 | 展示明确错误，游客宽限只覆盖游客态，不覆盖用户登录 |
| 运行时恢复与路由冲突 | 首页异常闪跳 | 使用 `LaunchGatePage` 承载异步恢复 |
| 主壳状态源不统一 | 卡片与用户中心显示不一致 | 统一读取 `AuthSessionStore` |
| 受限路由绕过 | 非 VIP 进入受限模块 | 在 `AppShellPage` 做 section 归一化 |
| 预览页误接正式逻辑 | 再次出现双轨实现 | 将 `preview_login.dart` 明确冻结为预览入口 |

### 22.2 业务风险

| 风险点 | 影响 | 应对措施 |
|---|---|---|
| VIP 权益判断错误 | 功能卡片状态错误 | 以前后端统一字段为真源 |
| 游客滥用 | 24小时试用被绕过 | 安装实例级绑定、宽限限制、服务端校验 |
| 演示数据残留 | 安全与体验风险 | 在收口步骤中强制删除 |
| 绑定表述过强 | 业务预期与实现不一致 | 文档明确写为安装实例级绑定 |
