# 日志与错误码规范

## 日志规则

- 日志格式统一为 JSON Lines
- 每条日志至少包含：`time`、`level`、`layer`、`module`、`task_id`、`event`、`message`
- 日志必须支持按 `task_id` 检索
- 日志默认脱敏，不得记录密码、验证码、token 明文

## 日志层级目录

| 目录 | 职责 |
|---|---|
| `logs/ui` | UI 操作与页面事件日志 |
| `logs/runtime` | Runtime 调度与状态流转日志 |
| `logs/worker` | Worker 执行与文件处理日志 |
| `logs/auth` | 登录、会话、权益相关日志 |

## 错误码前缀冻结

- `AUTH_*`
- `TASK_*`
- `INPUT_*`
- `IO_*`
- `WORKER_*`
- `RUNTIME_*`
- `NET_*`
- `SECURITY_*`
- `STATE_*`
- `PACKAGE_*`

## 首批最低错误码

| 错误码 | 含义 |
|---|---|
| `OK` | 成功 |
| `TASK_INVALID_INPUT` | 任务输入不合法 |
| `TASK_NOT_FOUND` | 任务不存在 |
| `INPUT_PATH_NOT_FOUND` | 输入路径不存在 |
| `WORKER_START_FAILED` | Worker 启动失败 |
| `RUNTIME_BRIDGE_UNAVAILABLE` | 本地桥接不可用 |

## 维护要求

- 新错误码必须先登记后使用
- 同义问题不得重复造码
- 已发布错误码不得随意改名
