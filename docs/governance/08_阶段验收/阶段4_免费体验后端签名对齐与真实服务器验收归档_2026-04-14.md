# 阶段4 免费体验后端签名对齐与真实服务器验收归档

## 归档信息

- 归档时间：2026-04-14
- 归档范围：`runtime/dj_runtime_py`、`apps/dj_flutter`、`docs/governance` 中与免费体验后端签名校验、本地完整性保护、trusted server time、恢复语义、真实服务器联调验收直接相关的实现与治理文件
- 当前状态：免费体验核心后端对接已完成签名与恢复语义对齐，真实服务器 `register/check/restore` 主链路已验证通过，已形成可恢复、可继续阶段5 联调的交接快照
- 对应阶段：阶段4 登录 / 用户中心 / 服务器对接

## 本阶段目标

- 将免费体验链路从“仅能请求服务器”提升为“按参考协议完成后端签名校验、本地完整性保护、trusted time 与恢复逻辑对齐”。
- 对齐免费体验 `register / check / restore` 的状态机语义，覆盖 `never_started`、`active`、`expired`、`unknown` 与 `need_network_validation`。
- 将真实服务器返回的免费体验字段接入 Flutter / Python runtime，避免继续依赖旧字段或本地猜测逻辑。
- 以真实服务器接口对免费体验主链路做至少一次可复现验收，形成阶段性交接结论。

## 当前状态结论

- 免费体验 Python runtime 已补齐 Ed25519 服务端签名校验、本地 HMAC 完整性签名、trust anchor 存储、trusted server time 推算与时间回拨检测。
- 免费体验 `register / check / restore` 已按当前参考文档对齐，`never_started` 不再误判为 `unknown`，本地离线恢复 active 会正确附带 `need_network_validation = true`。
- Flutter 侧 guest 相关模型已兼容 `server_time` 与 `last_server_time`，不会再只依赖旧字段做剩余时间恢复。
- 真实服务器主链路已实测通过：
  - 新机器首次 `check -> never_started`
  - 新机器首次 `register -> active`
  - 注册后 `check -> active`
  - 注册后 `restore -> active`
- 当前结论为：免费体验核心后端链路已进入“协议对齐完成 + 真实服务器主链路通过 + 可继续做阶段5 全局联调”的状态。

## 已完成内容

### 一、免费体验安全链补齐

- 新增 `trial_security.py`，内置服务端公钥，补齐 Ed25519 服务端签名校验、本地 HMAC 完整性签名、signed fields 序列化、trust anchor 更新与时间回拨检测。
- `secure_storage.py` 已新增 `guest_trust_anchor` 的存取与清理能力。
- `access_control.py` 已接入本地 guest session 完整性校验、服务端签名有效性校验、trusted server time 推算与回拨拦截。

### 二、免费体验状态机语义修正

- `guest_runtime.py` 已修正离线恢复逻辑：本地 active 且网络失败时，可保留 active，但必须标记 `need_network_validation = true`。
- `guest_runtime.py` 已修正远端 `never_started / not_registered` 语义：无签名的未领取态不再被误判为 `unknown`。
- 远端返回 `never_started` 时，会清理本地陈旧 guest session 与 trust anchor，避免旧 active 数据污染恢复链路。
- machine hash 不一致时，已清理本地免费体验 session、trust anchor 与访问缓存。

### 三、真实服务器字段接入与模型兼容完成

- `guest_service.py` 已固定对接：
  - `POST /api/guest/register`
  - `POST /api/guest/check`
- 真实服务器要求 `machine_hash` 长度为 64；当前 `machine_fingerprint.py` 生成值已满足该约束。
- `guest_service.py` 已支持在响应缺少 `server_time` 时，尝试从 HTTP `Date` 头回填。
- Flutter 侧 `auth_models.dart` 与 `auth_session_snapshot.dart` 已兼容 `server_time ?? last_server_time`。

### 四、测试与真实验收补齐

- 新增 `test_trial_security.py`，验证本地签名防篡改与 Ed25519 验签逻辑。
- 新增 `test_guest_runtime.py`，覆盖：
  - 离线 active 恢复需附带 `need_network_validation`
  - `never_started` 保持服务端状态，不强制降级为 `unknown`
  - `never_started` 清理陈旧本地 session
  - 本地过期恢复返回 `expired`
  - 本地篡改返回 `unknown + need_network_validation`
  - 时间回拨返回 `unknown + need_network_validation`
- 更新 `test_access_control.py`，使 guest 访问控制测试与当前运行时实现一致。
- 已通过运行时单测：
  - `python -m unittest test_trial_security.py test_guest_runtime.py test_access_control.py`
- 已通过真实服务器烟雾与主链路验收：
  - 真实 `check` 验证 `never_started`
  - 真实 `register` 验证 `active`
  - 注册后真实 `check`
  - 注册后本地 `restore`

## 验证结果

- 运行时单测已通过：`14 tests, OK`
- 真实服务器验证结果已确认：
  - `machine_hash` 长度不足会返回 `422`
  - 新机器首次 `check` 返回 `trial_state = never_started`
  - 首次 `register` 返回 `trial_state = active` 且包含 `issued_at / expires_at / server_time / sig`
  - `runtime` 对真实 `active` 响应的 `server_signature_valid` 为 `true`
  - `restore_guest_session` 与注册后 `check` 状态保持一致
- 本次边界验收已补齐本地过期、篡改、时间回拨三类场景。

## 风险与遗留问题

- 真实服务器 `expired` 分支尚未拿到现成过期 machine hash 样本，因此“线上真实 expired 响应”仍未完成最后一块实样验收。
- 服务端错签名场景在正常线上环境下不会主动出现，目前仅能通过本地测试思路验证，无法依赖生产服务器直接取样。
- 当前归档聚焦免费体验后端对齐，不代表阶段5 的全量联调、打包与所有功能模块端到端任务验收已经完成。
- Flutter/macOS 侧仍存在与本任务无关的历史构建与测试噪声，不在本次归档范围内。

## 对后续阶段的影响

- 阶段5 继续做全局联调时，免费体验链路应以本次归档为恢复现场入口，不再回退到旧的 guest token、旧字段或“无签名本地猜测”实现。
- 后续所有 guest session 恢复、权限判断与离线表现，必须沿用当前 `trial_security.py + guest_runtime.py + access_control.py` 的联合语义。
- 若继续补齐免费体验最终验收，应优先寻找或制造“真实 expired 样本”做最后一块端到端验收。
