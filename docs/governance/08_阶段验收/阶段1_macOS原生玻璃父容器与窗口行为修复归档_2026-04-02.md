## 关键问题与修复过程归档

### 一、纯 Flutter 假玻璃路线已降级为配合层

原先父容器尝试使用 Flutter 侧的透明层、假 blur、假高光来模拟玻璃效果，但这条路线无法实现 macOS 真正的 behind-window 材质采样效果。

已调整为：

- macOS 原生层使用 `NSVisualEffectView`
- Flutter 侧只保留：
  - 深藏青 tint 微调
  - 极轻表面反射
  - 极轻边界与压暗层
- Flutter 不再主导真实 blur

### 二、macOS 原生玻璃层已接入

已在 `MainFlutterWindow.swift` 内直接接入 `NSVisualEffectView`，未新增独立文件，未新增平台通道。

采用参数如下：

- `material = .underWindowBackground`
- `blendingMode = .behindWindow`
- `state = .active`

接入方式：

- 自定义 `ShellGlassContainerViewController`
- 使用该控制器作为 `contentViewController`
- 其中：
  - `visualEffectView` 负责原生玻璃材质
  - `flutterViewController.view` 负责 Flutter 主壳内容

### 三、窗口行为缺失项已补齐

在 `MainFlutterWindow.swift` 已补齐以下能力：

1. 窗口拖动：
   - `isMovableByWindowBackground = true`
   - 追加原生拖动热区视图承接拖动事件

2. 最小尺寸限制：
   - `minSize = 1280 × 820`

3. 最大尺寸限制：
   - `maxSize = 当前屏幕 visibleFrame`

4. 首次启动默认尺寸与居中：
   - 首次无历史记录时设为 `1440 × 900`
   - 执行 `center()`

5. 记住窗口位置/大小：
   - `setFrameAutosaveName("DjFlutterMainWindowFrame")`
   - `setFrameUsingName(...)`

### 四、拖动热区误覆盖问题已修正

早期修复阶段曾出现拖动热区覆盖过大，导致未来卡片区与工作区交互会受影响。

现已收窄为只覆盖真正空白区：

- 左侧窄边
- 右侧窄边
- 顶栏到卡片区之间的空白间隙
- 卡片区到工作区之间的空白间隙
- 工作区到底部状态栏之间的空白间隙

结论：

- 当前不再使用整块父容器全覆盖拖动热区
- 为后续子区域真实交互预留了空间

### 五、父容器四边边界线透明问题的根因与修复

#### 1. 问题表现

用户实机反馈：

- 上边、下边、左边、右边几乎都看不到边界线
- 最外层像漏透明

#### 2. 根因判断

根因不是单纯透明度太低，而是“边框画的位置错了”：

- macOS 原生层边框画在最外沿
- Flutter 层边框也画在最外沿
- 最外沿正好位于：
  - 原生材质边界
  - Flutter 裁切边界
  - 透明材质最容易被稀释的位置

最终导致：

- 视觉上边线被真实玻璃材质吃掉
- 四边像没有被稳定封住

#### 3. 当前修复方案

当前已改为：

- 去掉 macOS 原生 `visualEffectView.layer` 最外沿边框
- 改为 Flutter 侧在父容器内部绘制“内收式边界”

当前边界实现要点：

- 内收距离：`1.5px`
- 边线透明度：`0.09`
- 内收后圆角：`18.5`

结论：

- 当前边界线不再贴着最外缘画
- 已改为更稳定的“内收式可见边界”
- 这是比继续堆最外沿透明描边更合理的修法
