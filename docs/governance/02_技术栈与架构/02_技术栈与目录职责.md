# 技术栈与目录职责

## 三层技术栈冻结

| 层级    | 技术栈             | 主要职责                |
| ----- | --------------- | ------------------- |
| UI 层  | Flutter Desktop | 页面、交互、参数输入、结果展示     |
| 调度层   | Python          | 本地桥接、任务编排、会话管理、日志串联 |
| 核心执行层 | Rust            | 高性能扫描、查重、元数据处理、授权核心 |

## 边界规则

- Flutter 不直接调用 Rust
- Flutter 不直接请求远程服务器
- Python 不承担高强度核心计算
- Rust 不处理 UI 与远程登录流程
- 所有跨层通信统一使用 JSON，字段统一 `snake_case`

## 当前目录职责

| 目录                      | 主要用途               |
| ----------------------- | ------------------ |
| `apps/dj_flutter`       | Flutter 桌面端主应用     |
| `runtime/dj_runtime_py` | Python Runtime 主工程 |
| `crates/*`              | Rust 公共库、核心执行模块与预留目录 |
| `protocol/schemas`      | 协议定义               |
| `protocol/examples`     | 协议示例               |
| `docs/governance`       | 治理文档与归档资料          |
| `logs/*`                | 各层日志落盘目录           |
| `test_assets/*`         | 固定测试素材目录           |

## 当前架构目标

- 先建立壳，再建立链路
- 先验证一个模块闭环，再扩展其他模块
- 公共能力优先于模块内重复实现
- `crates/dj_common`、`crates/dj_license_core`、`crates/dj_meta_core`、`crates/dj_worker_bin` 当前仅为预留目录，尚未初始化为有效 crate，不纳入根 `Cargo.toml` 的 workspace members，也不参与 CI 编译测试
