# 认证服务器接口对接文档

## 一、文档说明

- 服务器基地址：`https://auth.jiaofangsi.top`
- 文档用途：提供当前项目登录 / 登出 / 权益 / 用户资料 / 游客试用相关服务器接口对接依据
- 适用范围：Flutter 前端、Python runtime、后端联调、测试联调
- 数据来源：
  1. 当前仓库实现代码
  2. `https://auth.jiaofangsi.top/openapi.json`
  3. 对线上接口的实际探测结果

> 注意：本文档以当前线上服务实际行为为准。若与旧计划书样例冲突，应以本文档和线上服务真实返回为准。

## 二、统一约定

### 2.1 请求头

#### JSON 请求

```http
Content-Type: application/json
```

#### 需要登录态的接口

```http
Authorization: Bearer <token>
```

### 2.2 时间字段

当前线上接口中同时出现两种时间格式：

1. 用户登录链路中，历史规划样例使用 ISO 8601 字符串
2. 游客试用链路中，线上真实返回使用 Unix 时间戳整数（秒）

联调时必须按各接口真实返回解析，不能统一假设都是 ISO 8601。

### 2.3 通用错误返回

#### 参数校验失败 `422 Unprocessable Entity`

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "login_name"],
      "msg": "Field required",
      "input": {
        "email": "invalid@example.com",
        "password": "invalid"
      }
    }
  ]
}
```

#### 未授权 `401 Unauthorized`

```json
{
  "detail": "登录已过期，请重新登录"
}
```

## 四、接口详情

# 4.1 用户登录

## 接口名称
用户登录

## 接口路径
`/auth/login`

## 请求方法
`POST`

## 请求参数

| 参数名称 | 数据类型 | 是否必填 | 说明 |
|---|---|---|---|
| `login_name` | string | 是 | 登录账号。根据线上真实接口，当前必须传 `login_name`，不能传 `email` |
| `password` | string | 是 | 登录密码 |

> 当前线上 OpenAPI 中未声明 `remember`、`auto_login`。如果客户端需要这些本地偏好，应仅存本地，不应直接假设服务端支持。

## 请求示例

```json
{
  "login_name": "user@example.com",
  "password": "password123"
}
```

## 返回数据结构

当前线上 `200` 返回为统一业务壳：

| 字段名称 | 数据类型 | 说明 |
|---|---|---|
| `success` | boolean | 是否登录成功 |
| `code` | string | 业务错误码或业务状态码 |
| `message` | string | 业务说明 |
| `data` | object | 登录结果数据 |
| `data.user_id` | string | 用户 ID，失败时可能为空字符串 |
| `data.login_name` | string | 登录名，失败时可能为空字符串 |
| `data.status` | string | 用户状态，失败时可能为空字符串 |
| `data.token` | string | 登录令牌，失败时可能为空字符串 |

## 成功响应示例

> 当前未持有真实成功账号，此处按服务端结构整理字段形态。

```json
{
  "success": true,
  "code": "",
  "message": "登录成功",
  "data": {
    "user_id": "12345",
    "login_name": "user@example.com",
    "status": "active",
    "token": "eyJhbGciOiJIUzI1NiIs..."
  }
}
```

## 失败响应示例

### 业务失败但 HTTP 仍为 200

```json
{
  "success": false,
  "code": "AUTH_FAILED",
  "message": "账号或密码错误",
  "data": {
    "user_id": "",
    "login_name": "",
    "status": "",
    "token": ""
  }
}
```

### 参数错误 `422`

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "login_name"],
      "msg": "Field required",
      "input": {
        "email": "invalid@example.com",
        "password": "invalid"
      }
    }
  ]
}
```

## 错误码说明

| 错误码 / 状态 | 含义 | 说明 |
|---|---|---|
| `AUTH_FAILED` | 登录失败 | 账号或密码错误 |
| `422` | 参数校验失败 | 例如缺少 `login_name` |
| `500` | 服务端异常 | 需后端排查 |

# 4.5 游客注册

## 接口名称
游客注册

## 接口路径
`/api/guest/register`

## 请求方法
`POST`

## 请求参数

| 参数名称 | 数据类型 | 是否必填 | 说明 |
|---|---|---|---|
| `machine_hash` | string | 是 | 机器指纹哈希，长度必须为 64 |
| `app_version` | string | 否 | 客户端版本号，最长 16，默认 `2.0` |

## 请求示例

```json
{
  "machine_hash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "app_version": "2.0"
}
```

## 返回数据结构

> 当前线上返回不是旧文档里的 `guest_token`，而是试用签名数据。

| 字段名称 | 数据类型 | 说明 |
|---|---|---|
| `expires_at` | integer | 过期时间，Unix 时间戳（秒） |
| `server_time` | integer | 服务端当前时间，Unix 时间戳（秒） |
| `remaining_hours` | number | 剩余可用小时数 |
| `nonce` | string | 随机串 |
| `sig` | string | 服务端签名 |

## 成功响应示例

```json
{
  "expires_at": 1775844063,
  "server_time": 1775757663,
  "remaining_hours": 24.0,
  "nonce": "e882e91b379c13f432d632a4e81ba0ec",
  "sig": "01e25365a825efbbb4398c69d53e8d984a66e37d900b539c5320eb29c8cabf83"
}
```

## 失败响应示例

### 缺少 `machine_hash`

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "machine_hash"],
      "msg": "Field required",
      "input": {
        "device_id": "debug-device-id"
      }
    }
  ]
}
```

### `machine_hash` 长度不足

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "machine_hash"],
      "msg": "String should have at least 64 characters",
      "input": "debug-machine-hash",
      "ctx": {
        "min_length": 64
      }
    }
  ]
}
```

## 错误码说明

| 错误码 / 状态 | 含义 | 说明 |
|---|---|---|
| `422` | 参数校验失败 | `machine_hash` 缺失或长度不合法 |

## 五、当前客户端与线上接口不一致点

以下是不一致的已确认问题，联调前必须修正：

| 模块 | 当前客户端字段 | 线上真实字段 | 状态 |
|---|---|---|---|
| 用户登录 | `email` | `login_name` | 不一致，必须修正 |
| 用户登录 | `remember` / `auto_login` 直传服务端 | OpenAPI 未声明 | 不应假设服务端支持 |
| 游客注册 | `device_id` | `machine_hash` | 不一致，必须修正 |
| 游客状态检查 | `guest_token` | `machine_hash` | 不一致，必须修正 |
| 游客注册响应 | 期望 `guest_token` | 实际返回 `expires_at/server_time/remaining_hours/nonce/sig` | 不一致，必须修正 |
| 游客检查响应 | 期望 `is_valid/is_expired/remaining_time` | 实际返回 `valid/expires_at/remaining_hours/server_time/nonce/sig/reason` | 不一致，必须修正 |
| 用户资料响应 | 期望 `email/nickname` | 实际返回 `ArtistProfileResponse.data` 完整资料结构 | 不一致，必须修正 |
| 权益响应 | 期望 `is_vip/features` | 实际返回 `EntitlementsResponse.data.entitlements[]` | 不一致，必须修正 |

## 七、文档结论

当前项目已经真实连接线上服务器 `https://auth.jiaofangsi.top`。其中用户登录、游客注册与游客状态检查链路已经过本轮阶段4 联调修正，guest 侧已完成以下对齐：

- 请求字段已统一为 `machine_hash`
- `register / check` 已按真实返回字段接入 `trial_state / issued_at / expires_at / remaining_hours / server_time / sig / reason / need_network_validation / valid`
- 免费体验服务端签名、本地完整性签名、trust anchor、离线恢复与时间回拨检测已落地到 Python runtime
- 真实服务器主链路已验证通过：
  - 新机器首次 `check -> never_started`
  - 新机器首次 `register -> active`
  - 注册后 `check -> active`
  - 注册后 `restore -> active`

当前仍未完成真实线上样本验收的仅剩 guest `expired` 实样与服务端错签名实样。后续所有登录认证联调工作，应以本文档、线上真实返回与阶段4 最新归档为准继续推进。
