# 协议与接口规范

## 最小协议原则

- 所有跨层协议统一使用 JSON
- 传输层字段统一使用 `snake_case`
- Flutter 内部模型允许保留 `camelCase`
- 响应壳统一使用 `ok`、`data`、`error`
- `task_id` 在 `start_*` 动作时创建
- 创建任务后的所有任务型动作必须携带 `task_id`
- 所有时间字段统一使用 ISO 8601

## 阶段4 登录 / 游客 / 权限表现补充规则

当前项目已完成真实登录、游客体验与主壳权限表现的阶段性落地。该部分虽不属于 Flutter <-> Python 的任务型 RPC 协议，但已形成需要冻结的联动规则，后续实现必须遵守。

### 真实认证服务器基线

- 认证服务器基地址：`https://auth.jiaofangsi.top`
- 用户登录接口：`POST /auth/login`
- 用户登录字段：`login_name`、`password`
- 游客注册接口：`POST /api/guest/register`
- 游客状态检查接口：`POST /api/guest/check`
- 游客请求字段：`machine_hash`

### 会员识别规则

当前会员识别不再只看 `vip`。

以下任一权益为 active，即视为可用会员：

- `vip`
- `dj_tool`
- `web_vip`

软件会员有效期解析优先级：

1. `dj_tool`
2. `vip`
3. `web_vip`

### 启动与路由规则

- 应用启动时固定先进入登录页
- 不允许依据本地快照自动跳过登录页直接进入主壳
- 只有真实服务端校验成功后，才允许进入主壳
- 登出后必须返回登录页，并由登录页负责窗口尺寸切换

### 游客体验规则

- 首次打开登录页可显示“免费体验”入口
- 点击后显示“正在分配试用凭证...”，成功后进入主壳
- 应用重新打开后，可恢复显示“体验剩余 HH:MM:SS”
- 游客体验到期后，游客按钮消失，“去开通”可进入提示态
- 游客体验用户可进入受限工作区的真实功能，不走非会员正式账号的锁定弹窗逻辑
- 游客态进入主壳时，不显示用户中心入口

### 免费体验后端对齐冻结规则

- 免费体验状态机以服务端 `trial_state` 为准，仅允许：`never_started`、`active`、`expired`、`unknown`
- 免费体验服务端签名字段冻结为：`machine_hash`、`issued_at`、`expires_at`、`trial_state`、`server_time`
- 服务端签名算法冻结为 `Ed25519`，签名编码格式冻结为 `base64`
- 本地必须同时维护：
  - 服务端签名有效性标记 `server_signature_valid`
  - 本地完整性签名 `local_signature`
  - 免费体验 trust anchor（`trusted_server_time`、`trusted_local_time`、`last_server_time`、`last_local_time`）
- 可信当前时间必须优先基于 trust anchor 推算，不允许只依赖本地系统时间直接判断 guest 是否有效
- 如检测到系统时间回拨，必须将免费体验状态收敛到 `unknown`，并设置 `need_network_validation = true`
- 本地完整性签名损坏、服务端签名无效、无法建立可信时间时，均必须进入 `unknown + need_network_validation = true`
- 当服务端明确返回 `never_started / not_registered` 时，不得因缺少 `sig` 将其误判为 `unknown`
- 当服务端明确返回 `never_started` 时，应清理本地陈旧 guest session 与 trust anchor，避免旧 active 数据污染恢复
- 当本地已有 active session 但联网校验失败时，可暂时保留 active 按钮，但必须设置 `need_network_validation = true`
- machine hash 不一致时，必须清理本地 guest session、trust anchor 与访问缓存后重新走 `check`

### 非会员正式账号权限表现规则

对于未开通 VIP / 工具会员的正式账号：

- 导航区可正常切换所有模块
- 模块页面完整显示，不允许用整页占位替换真实页面
- 除底部开始按钮外，其余配置、输入、拖拽、切换类控件应灰化并禁用交互
- 底部开始按钮允许点击
- 点击开始按钮后弹出“请开通会员后使用，免费体验期间也可使用。”提示弹窗

### 功能卡状态灯规则

- 绿色：`运行中`
- 橙黄色：`待机`
- 红色：`请开通会员后使用`

其中红色仅用于未开通 VIP / 工具会员的正式账号受限模块。

## unlock_music 输出目录当前冻结规则

- `lock_config.output_dir` 允许作为用户配置输入，但不保证最终执行目录与该输入字符串完全一致。
- `unlock_music` 在任务启动前必须完成输出目录归一化，不允许把“目录不存在”的问题延迟到任务执行中途才暴露。
- 当页面处于默认自动托管输出策略，且默认输出目录不存在时，系统必须在本次任务源目录公共父目录下创建一次任务级目录：`解锁输出-时间`。
- 同一批次 `unlock_music` 任务只允许创建一个任务级输出目录，不允许按单首歌曲逐个创建输出子目录。
- 完成弹窗、历史记录与“打开输出目录/文件夹”行为，必须指向本次任务实际写入的输出目录，遵循“输出到哪里就打开哪里”。
- Runtime 侧必须具备与 Flutter 侧一致的兜底语义；即使绕过 Flutter 直接调用 `unlock_music_service`，仍需在任务启动前完成目录创建与回写。

## 自动更新检查接口协议

### 接口定义

- **URL**: `GET https://www.jiaofangsi.top/api/update/check`
- **协议类型**: HTTPS REST（非 Flutter-Python RPC，为客户端直连远端服务器）
- **触发时机**: 客户端进入主壳后自动调用

### 请求参数（Query String）

| 参数 | 类型 | 必填 | 示例 | 说明 |
|------|------|:----:|------|------|
| `platform` | string | 是 | `macos` | 平台标识，当前固定为 `macos` |
| `version` | string | 是 | `V1.9.0` | 客户端当前版本号 |

### 响应格式

**无更新时：**

```json
{
  "has_update": false
}
```

**有更新时：**

```json
{
  "has_update": true,
  "version": "V1.10.0",
  "download_url": "https://www.jiaofangsi.top/downloads/dj_flutter_V1.10.0.zip",
  "release_notes": "1. 新增xxx功能\n2. 修复xxx问题",
  "file_size": 104857600
}
```

### 响应字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `has_update` | bool | 是 | 是否有可用更新 |
| `version` | string | 有更新时必填 | 最新版本号 |
| `download_url` | string | 有更新时必填 | 安装包下载链接（ZIP 格式） |
| `release_notes` | string | 否 | 更新说明，`\n` 换行 |
| `file_size` | int | 否 | 安装包字节数，用于显示下载进度 |

### 版本号比较规则

- 去掉 `V` 前缀后按语义化版本比较
- 服务器返回 `has_update: true` 当且仅当服务端最新版本 > 客户端版本

### 安装包要求

- 格式：ZIP
- 内容：解压后直接是 `dj_flutter.app`（不是嵌套目录）
- 下载链接必须支持 HTTPS

### 客户端行为

1. 无更新：按钮隐藏
2. 有更新：显示红色闪动下载按钮，点击下载
3. 下载完成：按钮提示"点击重启以更新"，点击执行替换并重启

## 后续维护要求

- 协议字段变更必须同步更新本文件
- 协议样例新增后应同时落到 `protocol/examples`
- schema 变更后应同步更新对应样例
- 任何跨层新接口都必须先补文档再接入实现
- `Python <-> Rust` 协议在 Python 调度层稳定后再冻结
